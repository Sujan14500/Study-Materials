# Two Projects, Taken Apart

An interactive walkthrough of [`refund-agent`](../refund-agent) and
[`support-platform`](../support-platform) — the two systems in this repo — in the same
format as the rest of these study materials.

Nineteen chapters. Every mechanism is something you can click, break and watch fail.

## Run it

Open `index.html` in a browser. No build, no server, no dependencies.

```
start index.html          # Windows
open index.html           # macOS
```

(Or `python -m http.server` and visit `localhost:8000`.)

## The interactions are ports, not mocks

This is the part that makes the page worth trusting. `demos.js` re-implements the real
logic in JavaScript:

| on the page | in the projects |
|---|---|
| `decide()` | `refund_agent/policy.py` |
| `buildIndex` / `search` / `confidence` / `gate` | `support/retrieval.py`, `support/agent.py` |
| `validateSql` | `support/store.py::TenantDB.select` |
| `reconcile` | `support/memory.py::LocalMemory._decide` |
| `makeTickets` | `support/seed.py::seed_history` |
| `runAsk` / `checkResult` | `support/analytics.py` |
| `evalTenant` | `support/evals.py::run_tenant` |

Re-implementations rot, and a walkthrough teaching a threshold that changed last month
is worse than no walkthrough. So:

```
python parity.py     # runs the actual Python modules, writes parity.json
node test.js         # runs the page's JS and asserts it agrees
```

`test.js` checks 18 policy cases (including every boundary), 27 retrieval probes across
three tenants, 11 SQL probes, and all three tenant eval scores — value for value against
the Python. It also verifies the tenant help-centre text and golden sets on the page are
byte-identical to `seed.py`, that every `#id` the demos reach for exists, and that every
path in the file-map chapters really is on disk.

Change a constant in `policy.py` without changing the page, and the test fails by name.

## Notes on accuracy

- The chaos and Ollama latency figures in chapter 7 are pasted from real runs of
  `refund-agent/chaos.py`, not simulated. The command is printed above each block so you
  can reproduce them.
- Chapter 15 recomputes the eval table live in the browser and matches
  `python evalgate.py` exactly — the test asserts it.
- Chapter 13 aggregates 140 tickets generated by a small LCG that mirrors
  `seed.py::seed_history` (same category weights, same per-category deflection rates).
  The numbers are internally consistent, not a capture of one Python run.
- The idempotency and saga chapters simulate the orchestration rather than running it —
  there is no SQLite in a browser tab. The step order, the compensation direction, the
  best-effort rule and the outcomes are the real ones.
- `bad auto` stays at zero in chapter 15 even at a reckless threshold. That is a property
  of these golden sets — every failing case retrieves nothing, and no-hits refuses
  unconditionally — not a promise from the gate. The page says so, and the test asserts it
  so the caveat gets updated if the seed data ever changes.
