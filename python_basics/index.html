Chapter 1 · Foundations

Everything is an object

An int, a string, a list, a function, a class — all objects, all with a type, all sitting somewhere in memory. Python has no "primitives" hiding in a corner. Get that straight now and the next ten chapters follow from it.

🔬 The type explorer

interactive

Click any literal. See what Python says about it: its type, whether it can be changed in place, and how it behaves inside an if.

🧊 Mutable vs immutable

The single most useful split in the language.

  • Immutable — int, float, str, bool, tuple, frozenset, None. Any "change" builds a new object.
  • Mutable — list, dict, set, and almost every class you write.
  • Only immutable objects can be dict keys or set members, because their hash must never change.
  • Only mutable objects can surprise you through aliasing — which is Chapter 2.

🎚️ Truthiness

if x: does not ask "is x True". It asks "is x truthy".

falsy:  False  None  0  0.0  ""  []  {}  set()
truthy: everything else — including
        "0", " ", [0], {0: None}

Which is why if items: is idiomatic, and why if count: is a bug the day count is legitimately 0.

💡
Type is on the object, not the name. x = 5 then x = "five" is perfectly legal — the name x just points somewhere else now. Python is dynamically typed but strongly typed: it will re-point a name freely and still refuse "1" + 1.

Take away

  • Every value is an object with a type, an identity and a value.
  • Mutable vs immutable decides what can alias, what can be a dict key, and what surprises you later.
  • Empty containers, 0, "" and None are falsy. Everything else is truthy.
Chapter 2 · Foundations

Variables are labels, not boxes

Most languages teach you that a variable is a box holding a value. Python is not like that, and every confusing bug you will hit in your first year comes from believing it is. A name is a label tied to an object. Assignment moves the label. It never copies the object.

🔗 Watch the arrows move

animated

Three tiny programs. Press Run and watch names on the left get wired to objects on the right, one line at a time. An amber arrow means two names share one object.

📋 How to actually copy

shallow = original.copy()   # or original[:]
shallow = list(original)

import copy
deep = copy.deepcopy(original)

A shallow copy gives you a new outer list whose items are still the same inner objects. If the list holds lists, you need deepcopy — or you have solved nothing.

🆔 is vs ==

a = [1, 2];  b = [1, 2];  c = a

a == b   # True  — same value
a is b   # False — different objects
a is c   # True  — the same object

x is None      # correct
x == None      # works, but never write it

is is for singletons: None, True, False. For everything else you mean ==.

⚠️
Passing to a function is assignment too. def f(items): items.append(1) mutates the caller's list, because the parameter is just another label on the same object. Python is neither "by value" nor "by reference" — it passes the reference, by value. Mutate and the caller sees it; rebind and they do not.

Take away

  • b = a creates a second name, never a second object.
  • Mutating (.append, += on a list, item assignment) is visible through every name bound to that object.
  • Rebinding (b = b + x) moves only that one name.
  • Immutable objects can never surprise you this way — they have no in-place change to make.
Chapter 3 · Core data

Text, and the ruler that cuts it

Strings are immutable sequences of characters. Every method returns a new string, slicing works the same way on every sequence in the language, and f-strings ended the formatting wars. Three ideas, most of your text handling.

💬 f-strings

    
The modern way to build a string. An f before the quote turns {...} into a live expression.

    

  


  

    
🧵

    
Building a string in a loop? s += piece creates a whole new string every iteration, because strings are immutable — that is O(n²) over the loop. Collect the pieces in a list and "".join(parts) at the end. On ten items it does not matter; on a hundred thousand it is the difference between instant and a coffee break.

  


  

    
Take away

    
    
      
  • String methods never modify — they return. s.strip() alone does nothing; you need s = s.strip().
    • 
      
  • [start:stop:step], stop exclusive, negatives from the end, and it never raises on over-range.
    • 
      
  • f-strings for everything, with format specs after the colon for money, percentages and alignment.

🧰 Moves worth memorising

      
list(set(items))              # dedupe
sorted(d.items(), key=lambda kv: kv[1])

d.setdefault("k", []).append(v)

📦 When the built-ins run out

      
    
        
  • Counter — counting anything, plus .most_common(3).
    • 
        
  • defaultdict(list) — grouping without the "does this key exist yet" dance.
    • 
        
  • deque — O(1) append and pop at both ends. The right queue.
    • 
        
  • namedtuple / dataclass — a tuple whose fields have names, and a class without the boilerplate.
    • 
      

      
from collections import Counter, defaultdict

by_dept = defaultdict(list)
for emp in staff:
    by_dept[emp.dept].append(emp)

    

  


  

    
Take away

    
    
      
  • Default to a list. Move to a dict the moment you find yourself searching by a key.
    • 
      
  • Any repeated membership test on a big collection wants a set.
    • 
      
  • Use a tuple to say "this is a fixed record and it will not change".
    • 
      
  • collections already solved counting, grouping and queues. Import, do not implement.

🔁 Loop like a Python programmer

      
# not this
for i in range(len(items)):
    print(items[i])

# this
for item in items: ...
for i, item in enumerate(items): ...
for a, b in zip(xs, ys): ...
for item in reversed(items): ...
for item in sorted(items, key=len): ...

      
If you are indexing to get the item, the loop is written wrong. range(len(x)) is the tell.

    

    

      
🚦 Conditions, compactly

      
if 0 < age < 18:          # chained, no `and`
if name in {"ada", "bob"}: # set literal
status = "adult" if age >= 18 else "minor"

match command.split():     # 3.10+
    case ["go", direction]:
        move(direction)
    case ["quit"]:
        raise SystemExit
    case _:
        print("unknown")

    

  


  

    
🧭

    
break, continue, else. break exits the loop entirely; continue skips to the next iteration. A loop can have an else, which runs only if the loop finished without breaking — useful for search loops ("if we got here, we never found it"), and confusing enough that a comment is usually kinder.

  


  

    
Take away

    
    
      
  • Indentation is the block structure. Four spaces, never tabs mixed in.
    • 
      
  • Iterate over items, not indexes. enumerate and zip cover almost every remaining case.
    • 
      
  • The loop variable outlives the loop — Python scopes by function, not by block.
    • 
      
  • When you cannot predict what a loop does, trace it: pen, paper, two columns. It always works.
    •

Arguments, and where they land

    
Python's argument handling is more flexible than most languages', which makes it powerful and occasionally baffling. Positional, default, *args, keyword-only, **kwargs — five mechanisms, one signature. Here is exactly where each call ends up.

🪤 The mutable default
animated

    
The most famous Python gotcha, and one that survives code review because it looks completely reasonable. Run it.

    

  


  

    

      
✍️ Writing a good function

      
def parse_age(text: str) -> int:
    """Return text as an age, or raise ValueError.

    Ages outside 0-130 are rejected rather than
    clamped: a bad value should be loud.
    """
    age = int(text)          # raises on junk
    if not 0 <= age <= 130:
        raise ValueError(f"age out of range: {age}")
    return age

      
    
        
  • One job. If the name needs an "and", split it.
    • 
        
  • Type hints are free documentation your editor can check.
    • 
        
  • Return a value or raise. Do not print and return None.
    • 
      

    

    

      
🔭 Scope, in four letters

      
x = "global"

def outer():
    y = "enclosing"
    def inner():
        z = "local"
        print(z, y, x)   # L, E, G
    inner()

      
LEGB: Local, Enclosing, Global, Built-in — the order Python searches. Assigning to a name anywhere in a function makes it local for the whole function, which is why reading it before that line raises UnboundLocalError. Use nonlocal or global only when you have run out of better ideas.

    

  


  

    
Take away

    
    
      
  • Positional by position, keyword by name, and after *args everything is keyword-only.
    • 
      
  • Defaults are evaluated once at definition time. Never make one mutable.
    • 
      
  • Mutating an argument mutates the caller's object. Say so in the docstring, or return a new one.
    • 
      
  • LEGB decides which name you get; assignment anywhere in the body makes it local.
    • 
    

  









  

    
Chapter 7 · Logic

    
The traceback is telling you

    
Beginners see a red wall and panic. It is the single most helpful thing Python prints. It names the exception, the message, the file and the exact line — and the fix is usually mechanical once you can read it.

  


  

    
🔍 Seven errors you will actually hit
animated

    
The traceback types in bottom-up — the order you should read it. The highlighted last line is the answer.

    

    

  


  

    
📖

    
How to read any traceback. Start at the bottom: exception type and message. Move up one line: the code that raised. Keep going up only if that line is inside a library — then look for the last frame that is your file. That is where the bad value came from.

  


  

    
🛡️ Handling, properly

    
Catch what you can actually deal with. Let everything else crash loudly — a crash you can see beats corrupt data you cannot.

    

  


  

    

      
🚫 Anti-patterns

      
try:
    risky()
except:            # catches KeyboardInterrupt too
    pass           # and now the bug is invisible

except Exception as e:
    print("error")  # loses the traceback entirely

      
If you must catch broadly, log the traceback: logging.exception("...") keeps the whole thing.

    

    

      
✅ Ask forgiveness, not permission

      
# LBYL — look before you leap
if os.path.exists(p):
    f = open(p)      # still races

# EAFP — the Python way
try:
    f = open(p)
except FileNotFoundError:
    f = None

      
Between the check and the use, the world can change. Try it and handle the failure.

    

  


  

    
Take away

    
    
      
  • Read tracebacks bottom-up. The last line is the what; the frames above are the how.
    • 
      
  • Catch specific exception types. Bare except: hides your own typos.
    • 
      
  • with beats try/finally for anything that must be closed or released.
    • 
      
  • Raise early at boundaries, with the offending value in the message.
    • 
    

  









  

    
Chapter 8 · Idiomatic

    
The loop that is an expression

    
A comprehension is the same loop, written as a description of the result. It is shorter, faster in CPython, and — once your eye adjusts — easier to read, because you see the shape of the output first.

  


  

    
🔄 Watch one build
animated

    
Same input every time: nums = [1, 2, 3, 4, 5]. Pick a form, press play, and watch which items survive.

    

  


  

    

      
🎓 The grammar

      
[ EXPR for ITEM in ITERABLE if CONDITION ]
   │        │                      │
   │        └─ the loop            └─ optional filter
   └─ what each surviving item becomes

      
Nested loops read in the same order you would write them:

      
flat = [x for row in grid for x in row]

# same as
flat = []
for row in grid:
    for x in row:
        flat.append(x)

    

    

      
🛑 When not to

      
    
        
  • More than one filter and a transform — that is a loop with a name, not a one-liner.
    • 
        
  • Anything you would need to comment inside. A comprehension has nowhere to put the comment.
    • 
        
  • Side effects. [print(x) for x in xs] builds a list of Nones for no reason; write the loop.
    • 
        
  • Three levels of nesting. Nobody has ever read that twice successfully.
    • 
      

      
The test: can you say it out loud in one breath? Then it is a comprehension.

    

  


  

    
💧

    
Drop the brackets and it becomes lazy. sum(x*x for x in nums) is a generator expression: values are produced one at a time and never collected. Any function taking an iterable — sum, max, any, all, join — should get one. That is how you process a file bigger than RAM.

  


  

    
Take away

    
    
      
  • [...] list, {k: v ...} dict, {...} set, (...) generator.
    • 
      
  • if after the for filters; if/else before the for chooses a value.
    • 
      
  • Generator expressions keep memory flat no matter how big the input is.
    • 
      
  • If it does not fit comfortably on one line, it was a loop all along.
    •

📦 Imports and modules

      
import math                 # math.sqrt(2)
from math import sqrt       # sqrt(2)
from mypkg import helpers   # your own code
import numpy as np          # conventional alias

if __name__ == "__main__":
    main()

      
A module is one .py file; a package is a folder of them. That last guard means "only run this when executed directly, not when imported" — without it, importing your script runs it.

    

    

      
🗂️ A layout that scales

      
myproject/
├── .venv/              # never committed
├── src/myproject/
│   ├── __init__.py
│   ├── core.py
│   └── cli.py
├── tests/
│   └── test_core.py
├── requirements.txt
└── README.md

      
Code in one place, tests beside it, dependencies pinned in a file. Boring, and it never becomes a problem.

Chapter 10 · Data & ML

    
NumPy, pandas and the data stack

    
Plain Python takes you a long way, and then someone hands you a two-million-row CSV. Everything from here is the same language with better containers underneath: one array type that holds numbers efficiently, and one table type built on top of it.

  


  

    
📦 Five packages, one job each

    
None of these ship with Python. python -m pip install numpy pandas matplotlib seaborn scipy — inside the venv from the last chapter, which is exactly what that chapter was for.

    

  


  

    
⚡ Why an array beats a list
animated

    
Same sum, two containers. Press run and watch how much work each one asks Python to do.

    

  


  

    
🧭

    
An array is not a list. A list holds pointers to objects of any type and grows freely. An array is one block of memory, one dtype, fixed size — that constraint is what makes arr.mean() fast and arr.append() not a thing. Reach for a list while you are collecting; convert once, at the end.

Take away

    
    
      
  • NumPy is the foundation: one dtype, one flat buffer, whole-array maths. Everything else stores its numbers there.
    • 
      
  • Whole columns at a time, never iterrows(). If you are writing a loop over a DataFrame, there is a shorter and faster expression.
    • 
      
  • df.shape, df.info(), value_counts() — run all three the moment data lands, before you believe anything about it.
    • 
      
  • pandas methods return new frames. Assign the result; inplace=True saves nothing and hides bugs.

Chapter 12 · Finish line

    
Nine things that will catch you once

    
Every one of these has cost a real person a real afternoon. Guess before you look — the ones you get wrong are the ones worth remembering.

quiz

    

  


  

    

      
🧮 Floats and money

      
>>> 0.1 + 0.2
0.30000000000000004

from decimal import Decimal
Decimal("0.1") + Decimal("0.2")   # 0.3 exactly

import math
math.isclose(a, b)                # comparing floats

      
Not a Python bug — it is IEEE-754, and every language has it. Money is integers of cents, or Decimal. Never a float.

    

    

      
🔒 Mutating while iterating

      
# skips items — the index shifts underneath you
for item in items:
    if bad(item):
        items.remove(item)

# do this instead
items = [i for i in items if not bad(i)]

      
Same for dicts: changing size during iteration raises RuntimeError. Iterate over a copy, or build a new one.

    

  


  

    
Take away

    
    
      
  • Most gotchas are one idea wearing different hats: names are labels, and defaults are evaluated once.
    • 
      
  • When something is genuinely surprising, open the REPL and check. Three seconds beats an hour of theory.
    • 
      
  • id(x) tells you which object you actually have when arrows get confusing.
